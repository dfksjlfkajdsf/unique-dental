2. CLOUDINARY IMPLEMENTATION (DEEP DIVE)
--------------------------------------------------------------------------------
Cloudinary has been implemented with a production-ready "dual-mode / graceful 
fallback" architecture in both the backend and frontend:

A. Architecture & Logic:
   - Config file: `dental-booking-system/src/config/cloudinary.js`
   - Detection function: `isCloudinaryConfigured()`
     Checks if either `CLOUDINARY_URL` is set OR all three (`CLOUDINARY_CLOUD_NAME`, 
     `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET`) are present and not equal to 
     the default placeholder string ('your_cloud_name').

B. How Uploads Work:
   - Route: POST `/api/v1/gallery` (Admin only, multipart/form-data via Multer)
   - When Cloudinary is CONFIGURED:
     1. The uploaded file is temporarily stored in local cache.
     2. `uploadToCloudinary(filePath, 'unique-dental/gallery')` sends the file to Cloudinary.
     3. Cloudinary returns a CDN `secure_url` and `public_id`.
     4. The local temporary file is automatically cleaned up and deleted from disk.
     5. The MongoDB `Gallery` model saves `imageUrl`, `cloudinaryPublicId`, and `source: 'cloudinary'`.
   - When Cloudinary is NOT YET CONFIGURED (Fallback mode):
     1. The file is saved directly to local disk in `uploads/gallery/`.
     2. Express serves it statically via `/uploads/gallery/:filename`.
     3. The MongoDB `Gallery` model saves `imageUrl: http://localhost:5000/uploads/gallery/...` 
        and `source: 'local'`.
     -> This ensures image uploading NEVER crashes or breaks even if Cloudinary credentials 
        are not yet set.

C. How Deletions Work:
   - Route: DELETE `/api/v1/gallery/:id` (Admin only)
   - If the image has a `cloudinaryPublicId`, it calls `cloudinary.uploader.destroy(publicId)`.
   - If stored locally, it safely deletes the file from `uploads/gallery/`.
   - The MongoDB database record is then removed.

D. Frontend Gallery Admin Indicator:
   - File: `dental-frontend/src/pages/admin/AdminGallery.jsx`
   - The backend `/api/v1/gallery` endpoint returns `cloudinaryConfigured: true/false`.
   - In the admin gallery header:
     * If active: Displays a green badge "● Cloudinary Active" with pulsing dot.
     * If inactive: Displays an amber badge "● Local Storage Mode (Cloudinary pending credentials)".

E. How to Enable Cloudinary:
   To switch from local storage to direct Cloudinary CDN hosting, open:
   `dental-booking-system/.env`
   and fill in your free Cloudinary credentials (from https://cloudinary.com):
     CLOUDINARY_CLOUD_NAME=your_actual_cloud_name
     CLOUDINARY_API_KEY=your_actual_api_key
     CLOUDINARY_API_SECRET=your_actual_api_secret

4. BACKEND SYSTEM SUMMARY (`dental-booking-system`)
--------------------------------------------------------------------------------
* Technology Stack:
  - Node.js (v24), Express 4, Mongoose 8, MongoDB
  - Multer (file uploads)
  - Nodemailer (email notifications & reminders)
  - Winston & Morgan (structured logging with combined.log and error.log)
  - Helmet & CORS (security headers & origin management)
  - Express Rate Limit (DDoS protection: 100 requests per 15 minutes)
  - Express Validator (input validation and sanitization)
  - Swagger UI Express (automated OpenAPI docs)

* Core API Endpoints:
  - Authentication (`/api/v1/auth`):
    * POST `/register` - Patient registration
    * POST `/login` - JWT authentication
    * GET  `/profile` - Current user profile
    * PATCH `/profile` - Update profile details
    * POST `/forgot-password` & `/reset-password`
  - Appointments (`/api/v1/appointments`):
    * POST `/` - Book appointment
    * GET  `/my` - Patient's own appointments
    * GET  `/` - Admin view all with date/status filters
    * PATCH `/:id/status` - Admin approve, complete, or cancel
    * PATCH `/:id/reschedule` - Reschedule date/time
  - Medical Records (`/api/v1/medical-records`):
    * Patient medical history, doctor prescriptions, diagnoses, and notes
  - Patient Directory (`/api/v1/admin/patients`):
    * Admin search and management of all registered clinic patients
  - Gallery (`/api/v1/gallery`):
    * GET  `/` - Public list with categories (Clinic, Team, Treatments, Smiles)
    * POST `/` - Admin multipart upload (Cloudinary + Local fallback)
    * DELETE `/:id` - Admin deletion with remote and local asset cleanup
  - System Health (`/api/v1/health`):
    * Ping test verifying backend and database connection status
